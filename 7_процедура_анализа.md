
# Процедура анализа

**Срок:** 26 сентября 2026 года  
**Статус:** рабочая версия; уточняется после пилотной разметки

## 1. Что определяется

**Единица анализа:**

Основной единицей анализа является **предложение**, содержащее потенциальный маркер митигации. Если значение маркера нельзя определить по одному предложению, анализируется расширенный контекст: предыдущее и последующее предложение.

**Дополнительными единицами являются:**

- текст — для анализа распределения маркеров по источникам и тематикам;
- словоупотребление — для фиксации конкретного маркера;
- многословная конструкция — для выражений типа *можно предположить*, *по всей видимости*, *в некоторой степени*;
- область действия — фрагмент предложения, который модифицируется маркером.

**Что приписывается единице:**

Для каждого потенциального случая фиксируются:

- наличие или отсутствие митигации;
- форма маркера;
- лемма или каноническая форма;
- тип митигации;
- область действия;
- коммуникативная функция;
- способ выражения;
- степень уверенности в разметке;
- источник, тема и жанровая подгруппа текста.

Минимальная запись в разметке должна иметь следующий вид:

| Поле | Содержание |
|---|---|
| `document_id` | Идентификатор текста |
| `sentence_id` | Идентификатор предложения |
| `marker_text` | Форма маркера в тексте |
| `lemma` | Лемма или нормализованная форма |
| `mitigation` | Да / нет |
| `type` | Тип митигации |
| `scope` | Область действия |
| `function` | Прагматическая функция |
| `source` | Источник текста |
| `topic` | Тематическая группа |
| `annotator` | Код разметчика |
| `confidence` | Уверенность разметки |

## 2. Система категорий

### 2.1. Основные категории

| Категория | Определение | Пример отнесения | Пример неотнесения |
|---|---|---|---|
| **Эпистемическая митигация** | Представление содержания как вероятного, предположительного или недостаточно подтверждённого | *Возможно, этот эффект связан с особенностями обработки информации.* | *Возможно, участники могут выбрать один из двух вариантов ответа.* — если речь идёт о реальной возможности действия, а не о степени достоверности утверждения |
| **Алетическая митигация** | Представление утверждения как одного из возможных вариантов объяснения или развития событий | *Можно предположить, что различия вызваны размером выборки.* | *Можно открыть файл через меню программы.* — инструкция, не связанная с ослаблением утверждения |
| **Аппроксимативная митигация** | Ограничение точности количества, степени, времени или частотности | *Около трети участников продемонстрировали сходную реакцию.* | *Около дома находился парк.* — пространственное значение |
| **Ограничение обобщения** | Сужение области действия утверждения по условиям, случаям или степени распространённости | *В ряде случаев наблюдается обратная зависимость.* | *В ряде случаев, перечисленных в таблице, использовался один и тот же метод.* — если выражение только отсылает к перечню случаев и не смягчает обобщение |
| **Авторизационная митигация** | Дистанцирование автора от утверждения посредством указания на источник, данные или позицию другого субъекта | *По данным исследования, эффект наблюдается не во всех группах.* | *Данные исследования опубликованы в приложении.* — библиографическая или фактическая информация без дистанцирования |
| **Оценочная митигация** | Ослабление положительной или отрицательной оценки | *Полученная интерпретация представляется не вполне убедительной.* | *Результат убедителен.* — категорическая оценка без смягчения |
| **Директивная митигация** | Смягчение совета, рекомендации, предложения или требования | *Было бы полезно проверить эту гипотезу на расширенной выборке.* | *Проверьте гипотезу на расширенной выборке.* — прямое требование |
| **Деперсонализирующая митигация** | Снижение прямой ответственности автора через безличные, пассивные или объектные конструкции | *Результаты позволяют предположить наличие двух факторов.* | *Мы доказали наличие двух факторов.* — прямое авторское утверждение |
| **Комбинированная митигация** | Сочетание двух или более функций в одной конструкции | *По-видимому, можно предположить, что эффект связан с возрастом.* | *Исследование показывает связь между возрастом и эффектом.* — нейтральное сообщение без митигационного элемента |

### 2.2. Отрицательный класс

В разметке необходимо выделять случаи **`NO_MITIGATION`**, когда потенциальная форма присутствует, но не выполняет митигационной функции.

**Примеры:**

- *Возможно* в значении реальной возможности действия;
- *около* в пространственном значении;
- *показывает* в нейтральном описании визуального материала;
- *очевидно* как усилитель категоричности;
- *можно* в инструкции;
- *кажется* в значении восприятия: *мне кажется, что поверхность шероховатая*.

Такой отрицательный класс необходим для обучения классификатора и проверки того, способен ли он отличать собственно митигацию от формального совпадения с маркером.

## 3. Порядок работы

1. **Фиксация корпуса.**  
   Каждому документу присваивается уникальный идентификатор. Сохраняются исходный текст, источник, дата, автор, URL, тематическая группа и тип публикации.

2. **Предварительная обработка.**  
   Из текста удаляются технические элементы, реклама, меню, дубли и дефектные фрагменты. Текст сегментируется на предложения и токены. Для каждого предложения сохраняется его позиция в документе.

3. **Формирование списка кандидатов.**  
   По корпусу выполняется поиск потенциальных маркеров по словарю лемм и многословных конструкций. Словарь включает эпистемические, аппроксимативные, авторизационные, оценочные и директивные выражения.

4. **Контекстная проверка кандидатов.**  
   Каждый найденный кандидат проверяется вручную в предложении и, при необходимости, в расширенном контексте. Фиксируется, является ли употребление митигационным.

5. **Разметка типа митигации.**  
   Для положительных случаев выбирается одна основная категория. Если маркер выполняет несколько функций, дополнительно указываются вторичные категории.

6. **Разметка области действия.**  
   Выделяется пропозиция, словосочетание или фрагмент, степень уверенности или категоричности которого изменяется маркером.

7. **Разметка функции.**  
   Указывается, что именно делает маркер: снижает уверенность, ограничивает обобщение, дистанцирует автора, смягчает оценку, ослабляет рекомендацию или уменьшает прямую ответственность автора.

8. **Проверка спорных случаев.**  
   Неоднозначные примеры помещаются в отдельный список и обсуждаются после завершения первичной разметки. Решения фиксируются в руководстве по аннотации.

9. **Формирование обучающих признаков.**  
   Для каждого предложения извлекаются:
   - леммы и словоформы;
   - части речи;
   - морфологические признаки;
   - наличие отрицания;
   - синтаксические зависимости;
   - положение маркера в предложении;
   - длина и тип конструкции;
   - наличие глаголов речи, знания, предположения и оценки;
   - признаки источника и тематической группы.

10. **Обучение классификатора.**  
    Сначала строится словарно-правиловый baseline. Затем проверяются классические модели машинного обучения, например логистическая регрессия, SVM или CRF, а при достаточном объёме данных — контекстная языковая модель.

11. **Оценка результата.**  
    Классификатор оценивается на независимой проверочной части корпуса по precision, recall, F1 и macro-F1. Для многоклассовой классификации метрики рассчитываются отдельно для каждого типа митигации.

12. **Корпусный анализ.**  
    После фиксации разметки рассчитываются:
    - абсолютная частотность маркеров;
    - частотность на 1000 слов;
    - распределение по типам митигации;
    - распределение по темам и источникам;
    - позиция маркеров в предложении;
    - частотность многословных конструкций;
    - доля неоднозначных и синкретичных случаев.

## 4. Спорные случаи

### Случай 1: `возможно`

*Возможно, результаты связаны с особенностями выборки.*

**Решение:** отнести к эпистемической митигации, поскольку автор снижает степень уверенности в причинном объяснении.

*Возможно проведение дополнительных экспериментов.*

**Решение:** отнести к алетической или директивной митигации только в том случае, если конструкция представляет потенциальное действие как допустимое предложение. Если это нейтральное описание технической возможности, маркировать как `NO_MITIGATION`.

### Случай 2: `очевидно`

*Очевидно, что результаты требуют дальнейшей проверки.*

**Решение:** не считать маркером митигации автоматически. В данном примере *очевидно* усиливает уверенность автора и относится к бустеру. Маркировать как `BOOSTER`, а не как `MITIGATION`.

*Как очевидно из приведённых данных, различия невелики.*

**Решение:** проверить контекст. Если слово используется как ссылка на очевидность для адресата и снижает необходимость прямого обоснования, оно может получить дискурсивную метку, но не должно автоматически включаться в класс митигации.

### Случай 3: `по данным исследования`

*По данным исследования, различия могут быть связаны с возрастом участников.*

**Решение:** выделить авторизационную митигацию, если конструкция переносит ответственность за сообщение на исследование и ограничивает прямую авторскую позицию.

*Данные исследования опубликованы в 2024 году.*

**Решение:** не считать маркером митигации, поскольку конструкция выполняет только информативную или библиографическую функцию.

### Случай 4: `примерно` и `около`

*Около 40% участников показали сходный результат.*

**Решение:** отнести к аппроксимативной митигации: точное значение заменяется приблизительной оценкой.

*Лаборатория находится около университета.*

**Решение:** маркировать как `NO_MITIGATION`, поскольку *около* имеет пространственное значение.

### Случай 5: `как правило`

*Как правило, подобные эффекты наблюдаются в условиях высокой нагрузки.*

**Решение:** отнести к ограничению обобщения, поскольку выражение не делает утверждение универсальным.

*Это правило, как правило, приводится в начале главы.*

**Решение:** также возможно отнесение к ограничению обобщения, если выражение ограничивает частотность действия. Если оно используется как устойчивая часть названия или цитаты, анализировать расширенный контекст.

### Случай 6: `показывает` и `позволяет предположить`

*Результат показывает наличие связи.*

**Решение:** не считать автоматически митигацией. Это может быть прямое категоричное утверждение.

*Результаты позволяют предположить наличие связи.*

**Решение:** отнести к деперсонализирующей и эпистемической митигации: ответственность переносится на результаты, а вывод представлен как предположение.

## 5. Если единица не подходит ни под одну категорию

Если кандидат не соответствует ни одной категории митигации, ему присваивается метка **`NO_MITIGATION`** с указанием причины:

- лексическое совпадение без митигационной функции;
- бустер или усилитель категоричности;
- нейтральное описание;
- пространственное, временное или количественное значение;
- инструкция;
- метаязыковое употребление;
- ошибка сегментации или токенизации;
- недостаток контекста.

Если функция потенциального маркера не может быть установлена даже после просмотра расширенного контекста, используется специальная метка **`UNCERTAIN`**. Такие случаи не включаются в основной обучающий набор до экспертного решения, но сохраняются для анализа неоднозначности.

Если конструкция содержит два независимых маркера, они размечаются отдельно:

*По-видимому, можно предположить, что эффект связан с возрастом.*

В этом примере:

- *по-видимому* — эпистемическая митигация;
- *можно предположить* — алетическая/эпистемическая митигация;
- область действия обоих маркеров — пропозиция *эффект связан с возрастом*.

## 6. Проверка воспроизводимости

**Кто выполнял независимый разбор:**

Основной разбор выполняет автор исследования. Независимый разбор должен выполнить второй лингвист или специалист по компьютерной лингвистике, не участвовавший в составлении первоначальной разметки.

**Объём проверочной выборки:**

Рекомендуется проверить:

- не менее 10% всего корпуса;
- не менее 500 предложений;
- все категории митигации;
- отдельно не менее 50 спорных случаев;
- тексты из всех тематических и источниковых подгрупп.

Выборка должна формироваться стратифицированно, чтобы в ней были представлены разные темы, источники и типы потенциальных маркеров.

**Совпадений:**

Заполняется после независимой разметки.

**Расхождений:**

Заполняется после независимой разметки.

Дополнительно рассчитываются:

- Cohen’s kappa для бинарной разметки `MITIGATION / NO_MITIGATION`;
- macro-F1 или Krippendorff’s alpha для многоклассовой разметки;
- отдельное согласие по выделению области действия;
- процент расхождений по каждому типу митигации.

**Характер расхождений:**

Расхождения классифицируются как:

- различие в определении наличия митигации;
- различие между близкими типами;
- различие в границах области действия;
- различие в интерпретации синкретичной конструкции;
- различие из-за недостаточного контекста;
- техническая ошибка разметки.

**Что уточнено по итогам:**

После независимой разметки уточняются:

- определения категорий;
- список маркеров и исключений;
- правила для омонимичных употреблений;
- границы области действия;
- порядок маркировки синкретичных случаев;
- правила обработки метки `UNCERTAIN`;
- критерий включения предложений в обучающий набор.

Окончательная версия руководства по аннотации фиксируется до обучения финальной модели.

## 7. Инструменты

**Чем выполняется анализ:**

- Python;
- pandas для обработки таблиц разметки;
- регулярные выражения для первичного поиска конструкций;
- spaCy, Natasha, Stanza или UDPipe для токенизации, лемматизации и морфологического анализа;
- синтаксический парсер для анализа зависимостей;
- pymorphy3 или аналогичный морфологический анализатор для проверки русских словоформ;
- scikit-learn для baseline-моделей;
- CRF-модель или sequence labeling для выделения области действия;
- pandas и scipy для частотного и статистического анализа;
- Doccano, INCEpTION или Label Studio для ручной разметки.

**Настройки и параметры, влияющие на результат:**

- версия используемого анализатора;
- модель токенизации и морфологической разметки;
- список стоп-слов, если он применяется;
- правила обработки дефисов, сокращений и чисел;
- версия словаря потенциальных маркеров;
- размер контекста;
- способ нормализации частотности;
- случайное зерно при разделении корпуса;
- доли обучающей, валидационной и проверочной выборок;
- параметры классификатора;
- критерии исключения коротких и повреждённых текстов.

Все параметры фиксируются в конфигурационном файле и сохраняются вместе с кодом.
